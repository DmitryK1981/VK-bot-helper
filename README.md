# VK AI Assistant (VKBottle + Gemini через ProxyAPI.ru)

AI-помощник для сообщества ВКонтакте (Bots Long Poll API): несколько независимых диалогов, память из
последних 100 сообщений с автоматической суммаризацией старых, 5 режимов общения, стриминг ответа,
защита от спама, JSON-хранилище, кнопочный интерфейс на русском.

## Возможности

- **Диалоги:** создание, список, переключение, переименование, удаление (с подтверждением). До 8 диалогов на пользователя; название нового диалога берётся из первого сообщения.
- **Режимы общения:** Обычный помощник, Программист, Преподаватель, Бизнес-консультант, Дружелюбный собеседник. Режим задаётся на диалог; при смене меняется только system prompt текущего диалога, история сохраняется.
- **Память:** в файле пользователя не более 100 последних сообщений диалога; более старые сворачиваются в краткое содержание (см. ниже).
- **Ответ ИИ:** «🤔 Бот думает…» + «печатает…», затем сообщение обновляется потоком по мере генерации; длинные ответы делятся на части.
- **Защита:** лимит запросов на пользователя, проверка пустых и слишком длинных сообщений, по одному ответу за раз, ретраи и резервная модель при сбоях Gemini.
- **Меню:** ➕ Новый диалог · 💬 Список диалогов · 🎭 Сменить режим · ⚙️ Настройки (режим, переименование, информация о модели, очистка истории) · ❓ Помощь. Текстовые команды: «меню», «начать», `/start`.

## Запуск

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env      # впишите VK_TOKEN и PROXYAPI_KEY
python -m bot               # точка входа: bot/bot.py
```

Настройка сообщества VK: *Управление → Сообщения* — включить сообщения сообщества и «Возможности ботов»;
*Работа с API → Long Poll API* — включить, тип событий «Входящее сообщение»; токен — с правом «сообщения».
Логи пишутся в консоль и в `logs/bot.log`, данные пользователей — в `users/<id>.json`.

Зависимости направлены вниз: `bot → services → storage/ai`. `services/` и `models/` не импортируют vkbottle.

| `services/` | `DialogManager`, `MemoryManager`, `ChatService`, `RateLimiter` |

| `tests/` | pytest: сервисы, хранилище, клавиатуры, обработчики на имитации VK |

## Ключевые решения

- **Кнопки = текстовые кнопки с payload.** Всё приходит как обычное сообщение и маршрутизируется правилом `CmdRule`; не нужны Callback-события и права на них. Клавиатура списка диалогов: строка `[переключить] [🗑 Удалить N]` (удаление — через экран подтверждения), лимит 8 диалогов вписывается в 10 строк VK.
- **Транзакции хранилища.** Любое изменение — `async with repo.transaction(user_id)`: блокировка → чтение → изменение → атомарная запись. Долгий вызов Gemini выполняется **вне** блокировки; в память пара «вопрос-ответ» пишется после успеха (неудачный запрос историю не засоряет), а если диалог удалили за это время — запись пропускается.
- **Роль хранится в диалоге**, system prompt собирается из роли при каждом запросе → смена режима затрагивает только текущий диалог и не портит историю.
- **Контекст:** `[system (роль + краткое содержание)] + последние 100 сообщений + новое user-сообщение`. Для Gemini `system` уходит в `system_instruction`, `assistant` → `model`. История, начинающаяся с ответа ассистента, обрезается до первой реплики пользователя.
- **Ожидание ответа:** «🤔 Бот думает...» + статус «печатает…» (обновляется каждые 4 с); заглушка редактируется в ответ, при сбое правки ответ отправляется новым сообщением; тексты > 4000 символов режутся по абзацам.
- **Отказоустойчивость:** ретраи на 429/5xx/сетевые сбои (экспоненциальный backoff), затем `GEMINI_FALLBACK_MODEL`, затем дружелюбное сообщение. Повреждённый JSON переименовывается в `*.corrupt-*.json`, пользователь получает чистое состояние.
- **Валидация:** пустые/вложения без текста и сообщения длиннее `MAX_USER_MESSAGE_LENGTH` отклоняются до обращения к модели. Сообщения одного пользователя обрабатываются строго по очереди.
- **Переименование** — двухшаговое: кнопка «✏️ Переименовать диалог» переводит пользователя в режим ожидания названия (`pending_action` в его JSON), следующее текстовое сообщение становится названием, а не вопросом к ИИ.

## Лимиты, стриминг и суммаризация

- **Лимит частоты** (`RATE_LIMIT_REQUESTS` за `RATE_LIMIT_WINDOW_SECONDS`): скользящее окно на пользователя; считаются только реальные запросы к ИИ (пустые и слишком длинные сообщения лимит не тратят). Пока бот отвечает на предыдущее сообщение, новое отклоняется с просьбой подождать.
- **Стриминг:** ответ идёт потоком (`generate_content_stream`), сообщение «Бот думает…» правится не чаще раза в `STREAM_EDIT_INTERVAL` секунд (защита от лимитов VK), с курсором «▌». Ретраи и fallback-модель работают до первого фрагмента; при обрыве посреди ответа пользователь видит уже пришедший текст и причину, в память такой ответ не попадает.
- **Суммаризация:** когда в диалоге больше `MAX_HISTORY_MESSAGES` (100) сообщений, в фоне самые старые (с запасом `SUMMARY_BATCH_SIZE`) сворачиваются в краткое содержание, которое хранится в диалоге (`summary`) и добавляется в system prompt. Если ИИ недоступен — старые сообщения просто отбрасываются; аварийный предел размера истории не даёт файлу расти бесконечно. «Очистить историю» удаляет и сообщения, и резюме.

## Пример запроса к Gemini через ProxyAPI

```python
from google import genai
from google.genai import types

client = genai.Client(
    api_key="PROXYAPI_KEY",
    http_options=types.HttpOptions(base_url="https://api.proxyapi.ru"),  # SDK сам добавит /v1beta/models/...
)
response = await client.aio.models.generate_content(
    model="gemini-3.1-flash-lite",
    contents=[
        types.Content(role="user", parts=[types.Part.from_text(text="Привет!")]),
        types.Content(role="model", parts=[types.Part.from_text(text="Здравствуйте!")]),
        types.Content(role="user", parts=[types.Part.from_text(text="Расскажи про asyncio")]),
    ],
    config=types.GenerateContentConfig(system_instruction="Ты — преподаватель.", temperature=0.7),
)
print(response.text)
```

## Как расширять

- **Другая модель** — `GEMINI_MODEL` в `.env`. **Другой провайдер** (OpenAI, Claude, локальная модель) — новый класс `LLMProvider` (методы `generate` и `stream`) и подстановка в `bot/bot.py`.
- **Новая роль** — добавьте `Role(...)` в `config/roles.py`; кнопки и тексты построятся сами (в клавиатуре ≤ 8 ролей).
- **Новая команда** — значение в `Cmd`, кнопка в `keyboards/menus.py`, обработчик с `CmdRule(...)`.

## Масштабирование

1. **Хранилище:** реализовать `UserRepository` для Redis/PostgreSQL — сервисы не изменятся (по требованиям сейчас только JSON).
2. **Несколько процессов/серверов:** локальные `asyncio.Lock` и `RateLimiter` действуют в одном процессе — нужны распределённые блокировки и счётчики (Redis) или шардирование пользователей по процессам; переход с Long Poll на Callback API за балансировщиком.
3. **Нагрузка и стоимость:** глобальная очередь запросов к LLM с ограничением параллелизма (`asyncio.Semaphore`), кэш частых ответов.
4. **Память:** считать токены (`countTokens`) вместо числа сообщений; хранить несколько уровней резюме для очень длинных диалогов.
5. **Наблюдаемость:** метрики (латентность, доля fallback/ошибок), структурные JSON-логи, алерты.
